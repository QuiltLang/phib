About

How Phib works

A grid of values. Each cell holds a term of an algebraic data type the world declares, such as type Ground += Belt(face: Dir).

Rewrite rules. Each recipe is a small picture: cells before, cells after, with variables that bind parts of terms. Every tick, each recipe that matches somewhere, in any of four turns, rewrites those cells.

One meaning, three engines. An interpreter runs the rules as written. Two compilers turn them into JavaScript and into WGSL for the GPU. All three must make the same boards; the stress test checks.

// The primes, by trial division: each number counts its divisors down.
type C = O | I(Nat<64>, Nat<64>)
cell C
recipe count
  I(n, _)  O  ->  *  I(n + 1, n)
recipe divide
  I(n, d)  ->  I(n, d - 1)
  where n mod d != 0

Where Quilt comes in

Quilt is a metaprogramming language: you write code that writes code with quotes, ↖…↗, and splice values into them with ↙…↘. Phib's code generators are Quilt, expanded ahead of time into plain JavaScript modules, so the page needs no Quilt at run time:

  • anchors.ts.quilt writes the JavaScript the compiler emits for each recipe's tests.
  • wgsl.ts.quilt writes the WGSL compute shader the GPU engine runs.
  • print.ts.quilt writes Phib itself: the printers the editor uses to save a redrawn recipe as text.
// print.ts.quilt: a Phib type, as written.

Stress test: Life

Its recipes are in Recipes. Here it runs on a big random board, by each of Phib's engines: the interpreter, the compiler to JavaScript, and the compiler to WGSL, on your GPU. Compare checks that all three make the same boards, then times them.

At 512² and up the interpreter takes seconds a tick, so Compare holds the page that long while it times it.
